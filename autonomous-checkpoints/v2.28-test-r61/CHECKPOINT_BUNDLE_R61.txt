===== CHECKPOINT_R61.txt =====
BRES CLÉS — CHECKPOINT V2.28 TEST R61

Objet : séparer l’identité physique des photos principales des autres changements d’interface afin de ne pas jeter à tort une session de profil valide.

Défaut reproduit en R60 :
- R60 liait la session profil à identificationEpoch ;
- identificationEpoch avance non seulement quand les photos recto/verso changent, mais aussi quand l’utilisateur modifie la référence, la marque ou les photos de tête ;
- une simple correction de texte ou une nouvelle photo de tête pouvait donc être interprétée comme « nouvelle clé » par compareProfilePhoto() ;
- la session profil et/ou sa capture pouvaient être écartées alors que les photos principales représentaient toujours la même clé.

Correctif R61 :
- ajout d’un mainPhotoEpoch dédié dans index.html ;
- mainPhotoEpoch avance uniquement dans photoRefresh(), donc lors d’un vrai changement des photos recto/verso ou d’une capture guidée principale ;
- la garde asynchrone générale identificationEpoch est conservée pour OCR, saisie manuelle et photos de tête ;
- v228-catalogue.js lie désormais les captures et sessions profil à mainPhotoEpoch ;
- repli compatible sur identificationEpoch si le wrapper R61 était exceptionnellement chargé dans un ancien shell ;
- test dédié PROFILE_MAIN_PHOTO_EPOCH_GUARD_TEST_R61.

Catalogue : 5 103 références uniques attendues ; les 10 morceaux de données catalogue restent strictement inchangés par rapport à R40/R60.
Sécurité : V2.27 reste stable sur main. R61 reste uniquement une version de test sur la branche v2.28-test-r1.

===== CODE_CHANGE_R61.txt =====
BRES CLÉS V2.28 TEST R61 — RÉSUMÉ DU CORRECTIF

- Ajout d’une époque dédiée mainPhotoEpoch dans le shell principal.
- Les changements de référence/marque et de photos de tête continuent d’invalider leurs calculs asynchrones via identificationEpoch, mais ne sont plus assimilés à un changement physique de clé pour le profil.
- Les captures/session profil utilisent mainPhotoEpoch pour détecter le vrai remplacement des photos recto/verso.
- Les données catalogue restent inchangées.
- La V2.27 stable n’est pas modifiée.

===== DEFECT_REPRO_R60_TO_R61.txt =====
BRES CLÉS V2.28 TEST R61 — REPRODUCTION DU DÉFAUT R60

1. En R60, currentMainIdentificationEpoch() lisait identificationEpoch.
2. identificationEpoch est incrémenté par photoRefresh(), mais aussi par les champs manualRef/manualBrand et invalidateHeadPhotoDerivedIdentification().
3. compareProfilePhoto() comparait cette valeur avec profileSessionMainEpoch/profileCaptureMainEpoch.
4. Une correction de texte ou une photo de tête pouvait donc déclencher la branche « Nouvelle clé détectée » sans changement recto/verso.

R61 introduit mainPhotoEpoch, avancé uniquement par photoRefresh(), et la chaîne profil se lie à cette époque dédiée.
