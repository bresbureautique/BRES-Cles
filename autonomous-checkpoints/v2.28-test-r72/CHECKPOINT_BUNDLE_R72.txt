===== CHECKPOINT_R72.txt =====
BRES CLÉS — CHECKPOINT V2.28 TEST R72

Objet : rétablir un état visible correct lorsque la base étalon partagée, précédemment corrompue, redevient valide ou est effacée depuis un autre onglet.

Défaut reproduit en R71 :
- R71 invalidait correctement les correspondances lorsqu’un autre onglet modifiait la base locale ;
- si cette base externe devenait corrompue, le statut rouge signalait correctement le problème ;
- si l’autre onglet réparait ensuite la base avec un JSON valide, le contrôle d’intégrité réussissait mais ne remettait pas à jour teachStatus ;
- le téléphone pouvait donc continuer à afficher « base endommagée » alors que la base réellement persistée était redevenue valide ;
- même défaut de statut après un effacement volontaire puis retour à une base valide.

Correctif R72 :
- checkStoredTemplateDBIntegrity() renvoie maintenant explicitement empty / valid / invalid ;
- lors d’un événement storage externe, le contrôle est exécuté en mode reportHealthy ;
- une base redevenue valide efface l’ancien message de corruption et affiche un état OK ;
- un stockage volontairement vidé affiche un état « base vide » explicite ;
- une vraie corruption ou une indisponibilité du stockage reste en erreur ;
- les correspondances dépendantes de la base restent invalidées : une nouvelle comparaison est toujours obligatoire.

Test renforcé : LOCAL_STORAGE_EXTERNAL_CHANGE_GUARD_TEST_R72.
Catalogue : 5 103 références uniques attendues ; les 10 morceaux catalogue doivent rester bit-identiques à R40/R71.
Sécurité : V2.27 reste stable sur main. R72 reste uniquement une version de test sur la branche v2.28-test-r1.
