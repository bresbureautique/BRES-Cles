===== CHECKPOINT_R63.txt =====
BRES CLÉS — CHECKPOINT V2.28 TEST R63

Objet : empêcher qu’un ancien import asynchrone de la base locale d’étalons remplace un fichier plus récent lorsque les lectures de fichiers se terminent dans le désordre.

Défaut reproduit en R62 :
- l’action d’import lisait directement le fichier courant puis attendait file.text() ;
- aucune session/époque d’import n’était figée avant cette attente ;
- si un fichier A lent était choisi puis un fichier B plus récent, B pouvait finir et être enregistré en premier ;
- lorsque A finissait ensuite, R62 exécutait quand même setDB(A) et remplaçait la base B pourtant sélectionnée plus récemment ;
- une erreur provenant de A pouvait aussi republier « Import impossible » après la réussite de B.

Correctif R63 :
- ajout de importFileEpoch dédié ;
- chaque changement du sélecteur d’import incrémente cette époque et fige l’objet File sélectionné ;
- après la lecture asynchrone et juste avant setDB(), R63 exige que l’époque et l’objet File soient toujours ceux de la sélection active ;
- le chemin d’erreur applique la même garde, donc un ancien import ne peut plus écraser le statut d’un import plus récent ;
- validation minimale du JSON : la racine doit être un objet et non un tableau ;
- ajout du test dédié IMPORT_ASYNC_GUARD_TEST_R63 avec reproduction simulée de la course R62 puis validation de la garde R63.

Catalogue : 5 103 références uniques attendues ; les 10 morceaux de données catalogue restent strictement inchangés par rapport à R40/R62.
Sécurité : V2.27 reste stable sur main. R63 reste uniquement une version de test sur la branche v2.28-test-r1.

===== CODE_CHANGE_R63.txt =====
BRES CLÉS V2.28 TEST R63 — CHANGEMENT CODE

Zone modifiée : import de la base locale d’étalons dans index.html.

Avant R63 :
  await fichier.text(); JSON.parse(...); setDB(...)
aucune vérification ne liait le retour asynchrone au fichier encore sélectionné.

R63 :
  const epoch=++importFileEpoch, input=..., file=input.files[0];
  await file.text();
  if(epoch!==importFileEpoch || input.files[0]!==file) return;
  JSON.parse(...);
  if(epoch!==importFileEpoch || input.files[0]!==file) return;
  setDB(...);

Le catch applique la même garde. Une ancienne lecture ne peut donc plus remplacer la base issue d’une sélection plus récente ni afficher un statut obsolète.
