===== CHECKPOINT_R65.txt =====
BRES CLÉS — CHECKPOINT V2.28 TEST R65

Objet : invalider immédiatement les résultats d’identification dépendants de la base locale après ajout ou modification d’un étalon.

Défaut reproduit en R64 :
- une comparaison pouvait afficher un gagnant local calculé avec la base d’étalons A ;
- l’utilisateur pouvait ensuite enregistrer une nouvelle prise d’étalon ou ajouter une nouvelle référence locale ;
- R64 écrivait correctement la nouvelle base mais laissait les anciens candidats et la décision précédente visibles ;
- l’écran pouvait donc présenter une conclusion calculée avant la modification de la base active.

Correctif R65 :
- après chaque écriture réussie d’un étalon local, invalidateLocalTemplateDependentResults() est appelée ;
- les correspondances locales, la décision finale, le visuel catalogue et les équivalences précédentes sont remis en attente ;
- currentSig est conservée puisque les photos principales n’ont pas changé ;
- une référence manuelle reste conservée mais doit être revérifiée ;
- le statut d’apprentissage demande explicitement de relancer la comparaison ;
- aucune équivalence n’est republiée automatiquement après l’invalidation ;
- ajout du test LOCAL_TEMPLATE_WRITE_INVALIDATION_TEST_R65 avec reproduction du comportement R64 puis validation du correctif R65.

Catalogue : 5 103 références uniques attendues ; les 10 morceaux de données catalogue restent strictement inchangés par rapport à R40/R64.
Sécurité : V2.27 reste stable sur main. R65 reste uniquement une version de test sur la branche v2.28-test-r1.

===== DEFECT_REPRO_R64_TO_R65.txt =====
BRES CLÉS — REPRODUCTION DÉFAUT R64 → CORRECTION R65

Scénario reproduit :
1. avec la base locale A, une comparaison affiche « TE8D — 91 % » ;
2. enregistrer un nouvel étalon ou ajouter une nouvelle référence locale ;
3. sans relancer la comparaison, observer l’écran.

R64 :
- la nouvelle base est correctement écrite dans localStorage ;
- l’ancien gagnant local reste pourtant affiché ;
- l’écran peut donc présenter un résultat calculé avec l’état précédent de la base.

R65 :
- la nouvelle base est écrite ;
- les candidats calculés avant l’écriture sont immédiatement retirés ;
- décision finale, visuel et équivalences sont remis en attente ;
- currentSig et la saisie manuelle restent disponibles ;
- il suffit de relancer la comparaison.

Preuve exécutable : local_template_write_invalidation_test.py et LOCAL_TEMPLATE_WRITE_INVALIDATION_TEST_R65.json/.txt.
