===== CHECKPOINT_R69.txt =====
BRES CLÉS — CHECKPOINT V2.28 TEST R69

Objet : sécuriser une base locale d’étalons déjà présente dans le téléphone lorsqu’elle est corrompue ou devenue incompatible.

Défaut reproduit en R68 :
- getDB() protégeait seulement l’erreur de syntaxe JSON en retournant une base vide ;
- une base JSON syntaxiquement valide mais de schéma corrompu pouvait encore atteindre match() et provoquer une erreur pendant la comparaison ;
- après une lecture corrompue, une nouvelle écriture pouvait repartir d’une base vide et remplacer silencieusement la valeur d’origine ;
- l’export normal ne préservait pas forcément la valeur brute nécessaire à une récupération.

Correctif R69 :
- toute base persistée est revalidée avec le même normaliseur que l’import avant d’être utilisée ;
- JSON illisible ou schéma invalide : erreur contrôlée, aucune écriture automatique et aucune modification de localStorage ;
- setDB() valide lui aussi la structure avant toute écriture ;
- un contrôle au démarrage affiche l’état corrompu sans faire planter l’application ;
- l’export crée BRES_base_etalons_RECUPERATION_R69.txt avec la valeur brute lorsqu’une base corrompue est détectée ;
- les bases historiques valides utilisant sig restent compatibles ;
- les données catalogue restent inchangées.

Test ajouté : LOCAL_DB_PERSISTENCE_GUARD_TEST_R69.
Catalogue : 5 103 références uniques attendues ; les 10 morceaux catalogue doivent rester bit-identiques à R40/R68.
Sécurité : V2.27 reste stable sur main. R69 reste uniquement une version de test sur la branche v2.28-test-r1.
