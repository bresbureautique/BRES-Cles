===== CHECKPOINT_R70.txt =====
BRES CLÉS — CHECKPOINT V2.28 TEST R70

Objet : rendre la base locale d’étalons tolérante à un stockage navigateur momentanément indisponible, interdit ou saturé.

Défaut reproduit en R69 :
- localStorage.getItem() appelé au démarrage pouvait lever SecurityError avant le bloc de protection et interrompre l’initialisation ;
- une lecture refusée remontait l’exception brute du navigateur ;
- localStorage.setItem() pouvait lever QuotaExceededError sans message explicite sur la conservation de la base précédente ;
- l’export de récupération pouvait à son tour échouer si localStorage lui-même était inaccessible.

Correctif R70 :
- lecture et écriture de la base étalon passent par deux passerelles contrôlées ;
- le contrôle de démarrage intercepte désormais aussi les refus d’accès au stockage ;
- quota dépassé et stockage inaccessible produisent des messages utilisateur distincts ;
- aucune écriture n’est considérée réussie si localStorage.setItem() échoue ;
- la base déjà stockée est préservée lors des erreurs simulées ;
- l’export brut reste disponible pour une base corrompue lisible, et un diagnostic est exporté si le stockage est illisible.

Test ajouté : LOCAL_STORAGE_AVAILABILITY_GUARD_TEST_R70.
Catalogue : 5 103 références uniques attendues ; les 10 morceaux catalogue doivent rester bit-identiques à R40/R69.
Sécurité : V2.27 reste stable sur main. R70 reste uniquement une version de test sur la branche v2.28-test-r1.
