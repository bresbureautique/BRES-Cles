BRES CLÉS — CHECKPOINT GITHUB R86

Objet : empêcher qu’une suppression d’étalon local confirmée avec retard écrase une modification plus récente de la base locale réalisée dans un autre onglet, sans toucher au catalogue ni à V2.27.

Défaut reproduit en R85 :
- la copie de base à supprimer était préparée avant window.confirm() ;
- pendant cette confirmation, un autre onglet de même origine pouvait modifier localStorage ;
- au retour de confirmation, setDB() pouvait réécrire la copie ancienne et perdre la modification externe.

Correctif R86 :
- existence de la référence vérifiée avant confirmation pour éviter les confirmations inutiles ;
- après confirmation, nouvelle lecture getDB() de la base persistée ;
- suppression recalculée sur cette base la plus récente ;
- les références ajoutées/modifiées ailleurs pendant la confirmation sont préservées ;
- si la référence ciblée a déjà été supprimée ailleurs, aucune écriture n’est effectuée ;
- ce changement externe avance l’époque locale et invalide les résultats dépendants ;
- les protections R85 de confirmation, capacité et non-destruction sur erreur de stockage restent conservées.
