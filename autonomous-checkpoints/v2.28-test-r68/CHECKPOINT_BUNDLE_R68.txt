===== CHECKPOINT_R68.txt =====
BRES CLÉS — CHECKPOINT V2.28 TEST R68

Objet : empêcher qu’un fichier JSON mal structuré mais syntaxiquement valide remplace la base locale d’étalons puis provoque des erreurs de comparaison.

Défaut reproduit en R67 :
- l’import vérifiait seulement que le JSON racine était un objet ;
- une entrée telle que {"TE8D":{"samples":"oops"}} était donc acceptée et écrite dans localStorage ;
- la comparaison locale pouvait ensuite itérer une valeur incompatible et échouer sur une signature non exploitable.

Correctif R68 :
- validation de chaque enregistrement avant toute écriture ;
- samples doit être un tableau de signatures géométriques valides ;
- chaque signature exige width_mm, height_mm, area, top et bot valides ;
- texture/colFill et bladeFill/headFill sont contrôlés lorsqu’ils sont présents ;
- les bases historiques utilisant un champ sig unique restent compatibles ;
- les références sont normalisées et les collisions après normalisation sont refusées ;
- une épaisseur présente doit être numérique et strictement positive ;
- un import comportant plus de 5 prises conserve les 5 plus récentes ;
- la base active n’est remplacée qu’après validation complète.

Test ajouté : LOCAL_DB_IMPORT_SCHEMA_GUARD_TEST_R68.
Catalogue : 5 103 références uniques attendues ; les 10 morceaux de données catalogue restent strictement inchangés par rapport à R40/R67.
Sécurité : V2.27 reste stable sur main. R68 reste uniquement une version de test sur la branche v2.28-test-r1.
