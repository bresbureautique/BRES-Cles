===== CHECKPOINT_R75.txt =====
BRES CLÉS — CHECKPOINT V2.28 TEST R75

Objet : empêcher un import de base étalon déjà en lecture d’écraser une modification plus récente de la base locale.

Défaut reproduit en R74 :
- l’import figeait bien le fichier choisi et utilisait importFileEpoch pour départager deux imports successifs ;
- en revanche, une modification de la base survenue pendant file.text() ne changeait pas cet importFileEpoch ;
- un événement storage provenant d’un autre onglet, ou un nouvel étalon enregistré dans le même onglet, pouvait donc être plus récent puis être écrasé par la fin tardive de l’ancien import.

Correctif R75 :
- une époque dédiée localTemplateEpoch représente désormais chaque mutation réussie de la base locale ;
- setDB() avance cette époque uniquement après une écriture localStorage réussie ;
- un événement storage externe sur la base, y compris localStorage.clear(), avance aussi cette époque ;
- l’import capture l’époque au démarrage et la revérifie après la lecture, après le parse, avant setDB() et dans le chemin d’erreur ;
- si la base a changé entre-temps, l’import ancien s’arrête sans écriture et sans remplacer le statut de l’action plus récente.

Test ajouté : LOCAL_DB_IMPORT_TEMPLATE_EPOCH_GUARD_TEST_R75.
Catalogue : 5 103 références uniques attendues ; les 10 morceaux catalogue doivent rester bit-identiques à R40/R74.
Sécurité : V2.27 reste stable sur main. R75 reste uniquement une version de test sur la branche v2.28-test-r1.
