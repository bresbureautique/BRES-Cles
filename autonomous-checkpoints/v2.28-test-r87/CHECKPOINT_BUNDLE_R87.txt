BRES CLÉS — CHECKPOINT GITHUB R87

Objet : empêcher une écriture locale obsolète d’écraser une modification concurrente de la base étalon entre sa dernière lecture et setDB(), sans toucher au catalogue ni à V2.27.

Défaut reproduit en R86 :
- R86 relisait la base après la confirmation de suppression, mais une fenêtre restait entre cette lecture et setDB() ;
- un autre onglet pouvait modifier localStorage dans cette fenêtre ;
- une suppression, un apprentissage ou un import pouvait alors persister un état préparé depuis un snapshot devenu ancien et perdre la modification concurrente.

Correctif R87 :
- les mutations lecture → modification → écriture utilisent un Web Lock exclusif nommé lorsqu’il est disponible, ce qui sérialise les onglets R87 participants ;
- une file Promise sérialise au minimum les mutations du même document si l’API Web Locks n’est pas disponible ;
- setDBIfRawUnchanged() compare immédiatement avant écriture les octets localStorage au snapshot utilisé pour préparer la mutation et refuse toute écriture devenue obsolète ;
- apprentissage, suppression et import utilisent cette garde ;
- l’apprentissage revérifie l’époque d’identification, l’époque de référence et la référence visible après attente du verrou ;
- l’import fige le snapshot brut de départ et refuse le remplacement complet si la base change pendant la lecture du fichier ;
- un conflit local_template_conflict est non destructif et produit un diagnostic explicite.
