===== CHECKPOINT_R64.txt =====
BRES CLÉS — CHECKPOINT V2.28 TEST R64

Objet : invalider immédiatement les résultats d’identification qui dépendent de la base locale lorsqu’une nouvelle base étalon JSON est importée.

Défaut reproduit en R63 :
- un résultat géométrique pouvait être affiché avec un candidat issu de la base locale A ;
- l’utilisateur pouvait ensuite importer une base locale B ;
- R63 remplaçait correctement les données dans localStorage, mais la liste de candidats, la décision finale et les preuves affichées restaient celles calculées avec A ;
- un candidat supprimé de B pouvait donc rester visible jusqu’à la prochaine comparaison.

Correctif R64 :
- ajout de invalidateLocalTemplateDependentResults();
- après setDB(o), l’import efface les candidats locaux affichés et remet décision/visuel/équivalences en attente ;
- currentSig est conservée car les photos n’ont pas changé ;
- une référence manuelle est conservée mais marquée à revérifier ;
- le message de succès demande explicitement de relancer la comparaison avant utilisation ;
- ajout du test LOCAL_DB_IMPORT_INVALIDATION_TEST_R64 avec reproduction du comportement R63 puis preuve de la règle R64.

Catalogue : 5 103 références uniques attendues ; les 10 morceaux de données catalogue restent strictement inchangés par rapport à R40/R63.
Sécurité : V2.27 reste stable sur main. R64 reste uniquement une version de test sur la branche v2.28-test-r1.
