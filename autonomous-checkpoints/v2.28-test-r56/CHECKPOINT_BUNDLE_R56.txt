===== CHECKPOINT_R56.txt =====
BRES CLÉS — CHECKPOINT V2.28 TEST R56

Objet : empêcher les sorties asynchrones intermédiaires d’un ancien cycle d’identification de réécrire l’interface après une nouvelle photo ou une nouvelle saisie.

Défauts reproduits en R55 :
- le logger de progression Tesseract écrivait directement dans ocrStatus sans vérifier l’époque d’identification ; après remplacement d’une photo, l’ancienne tâche pouvait donc réafficher « Lecture … » sur le nouvel état ;
- les blocs catch de l’analyse géométrique, de l’OCR principal et de l’OCR tête pouvaient publier une erreur provenant d’une tâche devenue obsolète ;
- le chargement asynchrone de l’aperçu d’une photo de tête pouvait finir après une sélection plus récente et dessiner l’ancienne image ;
- l’OCR des photos de tête utilisait le panneau de progression OCR principal au lieu de son panneau dédié.

Correctif R56 :
- bestOCR reçoit l’époque attendue et l’identifiant du panneau de statut ; toutes les progressions Tesseract passent par une publication protégée par l’époque ;
- une passe OCR devenue obsolète s’arrête dès le retour de Tesseract au lieu de continuer les orientations suivantes ;
- les erreurs asynchrones obsolètes sont ignorées dans analyse, OCR principal et OCR tête ;
- les aperçus de tête sont liés à l’époque de la sélection et ne peuvent plus écraser une sélection plus récente ;
- l’OCR tête publie sa progression dans headSearchStatus ;
- un test dédié verrouille ces comportements.

Catalogue : 5 103 références uniques ; les 10 morceaux de données catalogue restent strictement inchangés par rapport à R40/R55.
Sécurité : V2.27 reste stable sur main. R56 reste uniquement une version de test sur la branche v2.28-test-r1.

===== CODE_CHANGE_R56.txt =====
BRES CLÉS V2.28 TEST R56 — RÉSUMÉ DU CORRECTIF

- bestOCR(canvas,label,expectedEpoch,statusId) protège désormais toute progression Tesseract contre les résultats obsolètes.
- les passes OCR s’arrêtent après un await si l’époque a changé.
- runOCR(), searchFromHeadPhotos() et le gestionnaire d’analyse ignorent les erreurs arrivées d’un ancien cycle.
- drawPreviewFromFile() vérifie l’époque avant de publier un aperçu de tête.
- les lectures de tête utilisent headSearchStatus au lieu de polluer ocrStatus.
- version/cache-busting actifs passés à R56.
- catalogue de données inchangé.

===== DEFECT_REPRO_R55_TO_R56.txt =====
BRES CLÉS V2.28 TEST R56 — REPRODUCTION DU DÉFAUT R55

Le code R55 protégeait le résultat final des fonctions asynchrones, mais pas toutes leurs sorties intermédiaires.
Le logger Tesseract continuait à écrire directement dans ocrStatus pendant une ancienne reconnaissance ; les catch pouvaient aussi publier une erreur après changement d’époque ; et un aperçu de tête chargé lentement pouvait être dessiné après une sélection plus récente.

La sonde R55 dédiée échoue sur 6 points : absence d’époque dans bestOCR, logger non protégé, 3 catch non protégés et aperçu tête non protégé.
R56 ferme ces six fenêtres de course et les verrouille par async_ui_publication_guard_test.py.
