===== CHECKPOINT_R77.txt =====
BRES CLÉS — CHECKPOINT V2.28 TEST R77

Objet : conserver un diagnostic d’import exploitable quand le fichier JSON est invalide ou que le stockage local refuse l’écriture, sans affaiblir les gardes de concurrence R75/R76.

Défaut reproduit en R76 :
- toutes les erreurs d’import encore courantes aboutissaient au même message « Import impossible. » ;
- un JSON illisible, une base au mauvais schéma, un stockage local saturé et un stockage local indisponible devenaient donc indiscernables ;
- les protections étaient non destructives, mais l’utilisateur ne savait pas s’il devait corriger le fichier ou libérer/autoriser le stockage.

Correctif R77 :
- ajout d’un formateur d’erreur d’import dédié ;
- JSON syntaxiquement invalide → message clair « fichier JSON illisible ou invalide » ;
- schéma de base étalon invalide → message « format de base étalon attendu » ;
- erreurs de quota ou d’accès localStorage → conservation du diagnostic non destructif précis déjà produit par la couche de stockage ;
- les détails bruts inattendus restent masqués derrière un message de repli sûr ;
- la garde stopStaleImport reste prioritaire afin qu’une ancienne erreur ne puisse jamais remplacer le statut d’un import plus récent ;
- la remise à zéro sûre du sélecteur R76 reste active après erreur.

Test ajouté : LOCAL_DB_IMPORT_ERROR_MESSAGE_GUARD_TEST_R77.
Catalogue : 5 103 références uniques attendues ; les 10 morceaux catalogue doivent rester bit-identiques à R40/R76.
Sécurité : V2.27 reste stable sur main. R77 reste uniquement une version de test sur la branche v2.28-test-r1.
