===== CHECKPOINT_R59.txt =====
BRES CLÉS — CHECKPOINT V2.28 TEST R59

Objet : empêcher les retours asynchrones obsolètes de la caméra guidée du profil (section de clé).

Défaut reproduit en R58 :
- startProfileCamera() attendait getUserMedia() puis video.play() sans identifiant de session ;
- stopProfileCamera() arrêtait seulement le flux déjà publié, sans invalider une ouverture encore en attente ;
- après arrêt, remise à zéro ou nouvelle ouverture, une ancienne promesse getUserMedia/play pouvait donc republier son flux ;
- captureProfileCamera() écrivait directement capturedProfileBlob après toBlob(), sans vérifier que la caméra et la session étaient encore les mêmes ;
- une ancienne capture pouvait donc remplacer la photo de profil courante après un changement de session.

Correctif R59 :
- ajout de profileCameraEpoch, bumpProfileCameraEpoch() et profileCameraIsCurrent() ;
- stopProfileCamera() invalide désormais toutes les opérations caméra profil encore en attente ;
- chaque startProfileCamera() fige une session et arrête tout flux devenu obsolète ;
- captureProfileCamera() fige session, flux et dimensions avant toBlob(), puis refuse toute publication si la session a changé ;
- test dédié PROFILE_CAMERA_SESSION_GUARD_TEST_R59 verrouillant les trois protections.

Catalogue : 5 103 références uniques attendues ; les 10 morceaux de données catalogue restent strictement inchangés par rapport à R40/R58.
Sécurité : V2.27 reste stable sur main. R59 reste uniquement une version de test sur la branche v2.28-test-r1.

===== DEFECT_REPRO_R58_TO_R59.txt =====
BRES CLÉS V2.28 TEST R59 — REPRODUCTION DU DÉFAUT R58

Inspection reproductible de v228-catalogue.js R58 :
1. aucun profileCameraEpoch / identifiant de session n'existait ;
2. stopProfileCamera() n'invalidait aucune promesse getUserMedia/play encore en attente ;
3. startProfileCamera() exécutait directement `profileStream=await navigator.mediaDevices.getUserMedia(...)`, puis publiait ce flux sans vérifier qu'une fermeture ou une nouvelle ouverture avait eu lieu entre-temps ;
4. captureProfileCamera() exécutait directement `capturedProfileBlob=await new Promise(...toBlob...)` puis publiait profileCaptureMeta sans garde de session.

Reproduction statique sur R58 :
- profileCameraEpoch présent : NON
- stop invalide les opérations en attente : NON
- ouverture protégée par session : NON
- capture protégée après toBlob : NON
- publication directe `capturedProfileBlob=await ...` : OUI

Conséquence possible : après fermeture/remise à zéro/nouvelle ouverture, un ancien flux ou une ancienne capture pouvait reprendre la main et contaminer la session de profil suivante.
